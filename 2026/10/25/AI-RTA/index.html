AI Red Team Analyst Certification : Notes & Recap (CWL)

Author: Beylessen Jendoubi
Created: 2026-10-25
Updated: 2026-11-05
Certifications/Courses/Learning
AI DefenseAI PrivacyAI Red TeamingAI SecurityCWLMCPRAG

Around June 2026, I have finished the AI Red Teamer Job Role Path from HackTheBox.
This October, I have successfully acquired the AI Red Team Analyst (AI-RTA) certification from CWL.
To say the least, this has been a great refresher on the content I have mastered from HTB, plus a fun exam lab at the end to work on my MCP attacking skills.
Here’s a compressed look of what actually stuck, written in the way I’d explain it to someone with a traditional offensive security background.

The Curriculum Arc

The six modules build on each other cleanly:

M1–M2 are foundational to grasp the importance of AI as an attack surface and therefore ground to be defended. M3–M5 are the application layer : prompt manipulation, tool protocols, retrieval pipelines. M6 goes deep into the model itself: weight integrity, privacy attacks, backdoors. The progression is intentional and it pays off.

M1 : Why AI Red Teaming Is Its Own Discipline

The central point of M1 is that AI systems are probabilistic, not rule-based. You can’t enumerate valid states. The same input can produce different outputs across runs. Traditional red teaming assumes a deterministic target which once you find the edge case, you exploit it consistently. Here however, you’re working with a system that can be nudged rather than broken.

The 4-level pipeline attack model is the framework everything else hangs on:

Level Target
Infrastructure Cloud configs, API keys, CI/CD, model-serving hosts
Data Training sets, RAG stores, fine-tuning corpora
Model Weights, checkpoints, inference logic
Application Prompt composition, tool integrations, output handling

MITRE ATLAS(Adversarial Threat Landscape for Artificial-Intelligence Systems) is a knowledge base that documents real-world attacks against AI and ML systems.
It helps map how attackers target AI across different stages (16) like data, model, and deployment.
Red teams use ATLAS to plan attacks, simulate threats, and improve AI defenses.

M1 goes through a set of real-world AI incidents too.
The case study that stood out to me: SesameOp, malware that uses the official OpenAI Assistants API as its C2 channel. Commands encrypted and threaded through api.openai.com. From a network detection standpoint, that’s just standard HTTPS to a well-known endpoint. The blast radius of normalizing LLM API traffic is real.

M2 : The Mechanics You Need to Actually Attack These Systems

You can’t red team what you don’t understand. M2 is the foundation layer for everything that follows : tokenization, embeddings, attention, hyperparameters.

The security-relevant pieces:

Tokenization : tokens are not words. This matters because injection payloads that look identical to humans can tokenize differently. Character-level manipulation (homoglyphs, Unicode lookalikes) exploits the gap between human readability and token-level parsing.

Temperature & Sampling : the model’s randomness controls. High temperature = flatter probability distribution = lower-probability tokens become reachable. This is directly relevant for adversarial prompting: at high temperature, the model is more susceptible to being nudged toward low-probability outputs (like policy violations).

Context Window : the active memory ceiling. Everything in one inference window is processed with equal weight by the attention mechanism. There’s no privileged memory : system messages and user messages live in the same flat space. This is the root cause of most attacks, present in the third module.

The three red teaming pitfalls from this module:

  • Label Flipping during training : mark malicious payloads as benign, corrupt the decision boundary silently
  • Backdoor Triggers : embed a trigger pattern in the fine-tuning set; the model behaves normally on clean data and flips behavior on the trigger
  • Supply Chain / LoRA risks : a LoRA adapter from an untrusted repo inherits any backdoor from whoever built it

M3 : Prompt-Based Attacks

The attack surface here is the gap between system message intent and actual enforcement.

Direct Prompt Injection: You put the override in the user message directly.

This works more often than it should because system messages are not cryptographically enforced, they’re just text in a context window that the model has been trained to treat as authoritative. That training can be overridden.

Indirect Prompt Injection: The payload isn’t in your input : it’s in content the model retrieves and processes. You ask the model to summarize a webpage. The webpage contains:

The model parses that as instruction, not data. This is the harder class of attack to defend against because the malicious payload never touches your input validation layer.

Jailbreaking via Persona (DAN and derivatives): Roleplay framing that gets the model to adopt an identity with “no restrictions.” This is application-layer alignment bypass rather than a protocol vulnerability. It’s less interesting technically but still reliably effective in production systems with weak guardrails.

The dual-pipeline guardrail architecture is the standard mitigation: a filter before the model (input) and after it (output). The gap is indirect injection : the payload doesn’t touch the input filter because it arrives via tool output.

M4 : Model Context Protocol & Tool Security

MCP is the protocol that turns LLMs from text generators into actual agents : they can call APIs, read filesystems, query databases. The security model is, predictably, early-stage.

The five MCP primitives:

Primitive Role
Tools Active functions (web search, code exec, API calls)
Resources Passive data sources (files, databases)
Prompts Pre-structured templates
Capabilities Defined permission boundaries
Context-Sharing State sync across tools and sessions

The attack vectors that actually matter:

Description Typosquatting : LLMs select tools based on semantic matching of descriptions, not signatures. You register a malicious enterprise_commit() with a convincing description alongside a legitimate git_commit(). The model picks the deceptive one. There’s no hash verification step in the selection process.

Indirect Injection via Tool Outputs : tool responses are treated as trusted context. If a web-fetch tool returns a page containing:

the model can execute that instruction before you’ve had a chance to review anything.

Command Injection on the Server : if the MCP server doesn’t sanitize tool arguments before passing them to system calls, you get RCE. This isn’t novel; it’s the same class as command injection in traditional web apps. What’s different is the injection source: a natural language input that the AI translated into a function call.

The HITL gap: autonomous agents executing tool chains without human-in-the-loop approval dramatically amplify any of the above. One compromised tool call can chain into lateral movement across whatever the agent has credentials for.

M5 : RAG & Multi-Agent Systems

RAG solves the “model doesn’t know current information” problem by retrieving documents at runtime and injecting them into the prompt context. The security problem is that retrieval is semantic, not permission-aware.

The retrieval step doesn’t check whether the user is authorized to see the retrieved content. It checks cosine similarity. A document with high semantic relevance to a query gets retrieved regardless of its access control metadata unless you build that check explicitly into the pipeline.

Three attack classes here:

Knowledge Base Poisoning : upload a malicious document into the knowledge base. When a user asks a relevant query, the vector search retrieves your document, and the LLM treats it as ground truth.

Access Control Bypass : the retrieval pipeline returns documents the user shouldn’t be able to read. The LLM then synthesizes them into a response. The user effectively read restricted data through the generation layer.

Indirect Prompt Injection via Retrieved Docs : hide instructions in a document. When retrieved, those instructions execute in the model’s context mid-generation.

For multi-agent systems, the problem compounds: downstream agents implicitly trust outputs from upstream agents. A single compromised upstream agent can redirect an entire agent chain. There’s no built-in attestation model for inter-agent communication. Privilege chaining (combining permissions across multiple agents to reach access levels no single agent holds) is the threat pattern to design against.

M6 : Model-Level Attacks, Privacy & Lifecycle Security

This is the deepest module and the one most relevant to my actual work in adversarial ML.

Evasion vs. Poisoning vs. Backdoors

Evasion Poisoning Backdoor
When Inference time Training / fine-tuning Training, fine-tuning, or checkpoint edit
Goal Misclassification Accuracy degradation or bias Dormant trigger activation
Weight change No Yes Yes
Clean input behavior Normal Degraded 100% normal

The backdoor concealment property is the operationally scary one. A backdoored model passes standard accuracy benchmarks. You can’t find it by evaluating on clean data. You need explicit trigger sweep testing or weight inspection.

Privacy Attacks

Membership Inference Attack (MIA): Does record X appear in this model’s training set? You train a shadow model on known-in / known-out samples, teach it to distinguish the probability variance patterns, then probe the target. The root cause is overfitting because models that memorize rather than generalize produce distinctly higher confidence scores on training samples.

Model Inversion: Reconstruct raw training inputs from output confidence scores. The classic example is reconstructing facial images from a facial recognition model’s outputs. In text, this means recovering private training records from a language model.

Model Extraction: Repeatedly query the target model and train a student model on the query-response pairs. You steal the model’s functional behavior and potentially its embedded knowledge of private training data without ever touching the weights directly.

Adversarial Perturbations

Specially crafted inputs that appear benign to humans but trigger misclassification in the model:

Text:

  • Character-level: Unicode homoglyphs : visually identical to ASCII but tokenize differently. аttack (Cyrillic а) vs attack (Latin a). Passes human review, breaks classifier.
  • Word-level: Synonym substitution shifts the embedding vector while preserving meaning to human readers
  • Sentence-level: Appending irrelevant noise blocks to skew classification scores

Image:

  • Full-image noise: Imperceptible mathematical noise across pixels that flips the classification output
  • Single-pixel attack: Tweak one pixel’s RGB values to exploit localized non-linearity in the decision boundary
  • Pixel-embedded prompts: Embed command text directly into image pixel values, invisible to human review but readable by the AI parser

Audio:

  • Waveform tweaks: Modify continuous audio signals to fool ASR systems
  • Hidden voice commands: Ultrasonic or inaudible commands embedded in background noise (the Amazon Alexa wake-word injection case)
  • Frequency shifts: Minor adjustments that alter TTS transcription while sounding normal to human ears

Multimodal: Coordinated imperceptible perturbations across text + image + audio simultaneously designed specifically to bypass safety filters that evaluate modalities in isolation.

Cross-Module Threads

Three themes appear repeatedly across the curriculum that are worth naming explicitly:

The trust model problem : system prompts, tool outputs, retrieved documents, inter-agent messages. None of these are cryptographically attested. They’re all just text in a context window that the model has been trained to treat as coming from a trusted source. The attack surface is anything that can put adversarial text into that trusted position.

The indirect injection blindspot : input validation catches direct injection. It doesn’t catch payloads that arrive through retrieval, tool execution, or agent communication. The surface moves past where defenders are looking.

The overfitting-privacy link : a model that overfits has memorized its training data. Memorized training data is recoverable via membership inference and model inversion. The standard ML engineering heuristic (more data + regularization) is also the privacy engineering answer.

What I’m Taking Forward

Most of what the curriculum covered mapped onto things I’d reasoned through informally, it just gave me sharper language for them. MCP was where I actually had to stop and rebuild my mental model from scratch.

The exam-relevant takeaways in one place:

  • Poisoning happens at training time; evasion happens at inference time
  • Backdoors pass clean-data evaluation — you need trigger sweep testing
  • RAG retrieval is permission-unaware by default
  • Tool descriptions are the attack surface for agent tool selection
  • Overfitting is a privacy vulnerability, not just an accuracy problem
  • Indirect injection bypasses every input-layer defense
